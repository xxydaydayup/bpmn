# Vue 工作流设计器与 BPMN 编辑器并存

**Status: accepted**

当前 `bpmn` 项目中的 `bpmn-js` 编辑器直接维护 BPMN 模型和 XML；另一个 React 应用中的 React Flow 设计器则编辑业务工作流模型，并交由后端编译为 Camunda BPMN XML。决定在本项目增加独立的 Vue 3 / Vue Flow 业务工作流设计器，与现有 BPMN 编辑器并存，不复用 React 或 `bpmn-js` 的实现代码，也不改变现有 XML 编辑和部署契约。这样可以让业务模型设计器作为 Vue 能力交付，同时保留需要直接维护 BPMN 语义和 XML 的场景。

新设计器首版实现当前 `WorkflowModel` v1 的画布映射、校验、撤销/重做和自动布局；它不直接维护 BPMN XML，也不持有宿主系统的鉴权、持久化和 API 能力。由宿主传入的编译与发布回调可分别编译为 BPMN XML、将其发布为业务任务模板；设计器不承担运行时操作。前端以版本化 JSON Schema 和标准样例共享编译契约，而不共享 React 组件或状态代码；正式 Schema 由后端编译器维护方作为唯一来源。在该来源可用前，以现有 `workflow` 项目的模型定义及业务样例为迁移基线。当前业务模型没有显式版本字段，按 v1 处理，并保持编译接口要求的模型结构，包括节点 `x` / `y` 坐标。

## 决策

- 在 `bpmn` 仓库内以 pnpm workspace 组织独立 Vue 3 设计器包和宿主示例；首版不发布 npm。设计器包暴露公开组件入口及类型，现有 Vue 应用负责示例集成。
- Vue 设计器独立实现画布节点/边、状态、校验及模型映射；公开支持的扩展点限于现有节点的展示、属性编辑、默认值、节点库、连接规则、校验、主题和插槽。扩展不得自行引入 JSON v1 未定义的业务语义。
- 设计器通过 `v-model` 提供版本化完整设计稿，通过宿主提供的 `compile(model)` 回调进行编译。宿主拥有鉴权、保存、API 地址、请求实现和编译结果后续操作；设计器不依赖宿主 UI 库或应用级状态/API 封装。
- 编译时只向宿主回调传递受支持且经过校验的当前业务模型。新增节点或影响编译的新字段，须先升级正式业务 JSON 契约并实现后端编译能力。
- 完整设计稿使用独立版本化信封，内含业务模型和编辑器状态（视口、主题、连线路由点及受支持的宿主展示扩展）；该版本与业务模型、编译 API 版本分别管理。旧版裸 `WorkflowModel` JSON 可导入，并包装为当前设计稿格式。
- 未知业务字段应在导入、编辑和导出过程中保留；存在未识别的业务字段或未知业务节点时，禁止编译。未知节点以不可编辑占位展示。无法识别的新版设计稿信封以只读方式打开并原样保留；只有明确位于非编译展示扩展区的数据不会阻止编译。
- Vue 和 Vue Flow 由宿主提供；Tailwind 仅作为设计器包的构建依赖，构建输出独立、使用命名空间且不含全局 reset 的 CSS。模块不依赖 Element Plus、Ant Design 等宿主控件库，并通过 CSS 变量及公开插槽提供样式定制能力。

## 后果

- 画布状态与业务工作流模型之间需要显式映射；业务模型里的坐标属于当前编译输入契约，即使设计稿另存视口和连线路由状态也不能在未升级契约时从编译请求中删除坐标。
- 两个设计器可以在同一应用中独立演进，但入口和文档应区分“业务工作流模型设计”与“BPMN/XML 建模”，避免把可编译的业务模型误认为完整 BPMN 能力。
- 在后端正式 Schema 发布前，跨仓库的模型兼容通过版本化 Schema/样例副本和契约检查维护；后端契约来源明确后，前端类型和映射须跟随它更新。
- 未知业务数据采用保守的只读/禁编译策略，避免旧版设计器静默丢弃未来语义或生成不完整流程。

# Vue 工作流设计器与 BPMN 编辑器并存

**Status: accepted**

当前 `bpmn` 项目中的 `bpmn-js` 编辑器直接维护 BPMN 模型和 XML；另一个 React 应用中的 React Flow 设计器则编辑业务工作流模型，并交由后端编译为 Camunda BPMN XML。决定在本项目增加独立的 Vue 3 / Vue Flow 业务工作流设计器，与现有 BPMN 编辑器并存，不复用 React 或 `bpmn-js` 的实现代码，也不改变现有 XML 编辑和部署契约。这样可以让业务模型设计器作为 Vue 能力交付，同时保留需要直接维护 BPMN 语义和 XML 的场景。

新设计器首版实现当前 `WorkflowModel` v1 的画布映射、校验、撤销/重做和自动布局；它不直接维护 BPMN XML，也不持有宿主系统的鉴权、持久化和 API 能力。由宿主传入的编译与发布回调可分别编译为 BPMN XML、将其发布为业务任务模板；设计器不承担运行时操作。前端以版本化 JSON Schema 和标准样例共享编译契约，而不共享 React 组件或状态代码；正式 Schema 由后端编译器维护方作为唯一来源。在该来源可用前，以现有 `workflow` 项目的模型定义及业务样例为迁移基线。当前业务模型没有显式版本字段，按 v1 处理，并保持编译接口要求的模型结构，包括节点 `x` / `y` 坐标。

## 决策

- 在 `bpmn` 仓库内以 pnpm workspace 组织独立 Vue 3 设计器包和宿主示例；首版不发布 npm。设计器包暴露公开组件入口及类型，现有 Vue 应用负责示例集成。
- Vue 设计器独立实现画布节点/边、状态、校验及模型映射；公开支持的扩展点限于现有节点的展示、属性编辑、默认值、节点库、连接规则、校验、主题和插槽。扩展不得自行引入 JSON v1 未定义的业务语义。
- 设计器通过 `v-model` 提供版本化完整设计稿，通过宿主提供的 `compile(model)` 回调进行编译。宿主拥有鉴权、保存、API 地址、请求实现和编译结果后续操作；设计器不依赖宿主 UI 库或应用级状态/API 封装。
- 编译时只向宿主回调传递受支持且经过校验的当前业务模型。新增节点或影响编译的新字段，须先升级正式业务 JSON 契约并实现后端编译能力。
- 完整设计稿使用独立版本化信封，内含业务模型和编辑器状态（视口、主题、连线路由点及受支持的宿主展示扩展）；该版本与业务模型、编译 API 版本分别管理。旧版裸 `WorkflowModel` JSON 可导入，并包装为当前设计稿格式。
- 未知业务字段应在导入、编辑和导出过程中保留；存在未识别的业务字段或未知业务节点时，禁止编译。未知节点以不可编辑占位展示。无法识别的新版设计稿信封以只读方式打开并原样保留；只有明确位于非编译展示扩展区的数据不会阻止编译。
- Vue 和 Vue Flow 由宿主提供；Tailwind 仅作为设计器包的构建依赖，构建输出独立、使用命名空间且不含全局 reset 的 CSS。模块不依赖 Element Plus、Ant Design 等宿主控件库，并通过 CSS 变量及公开插槽提供样式定制能力。

## 后果

- 画布状态与业务工作流模型之间需要显式映射；业务模型里的坐标属于当前编译输入契约，即使设计稿另存视口和连线路由状态也不能在未升级契约时从编译请求中删除坐标。
- 两个设计器可以在同一应用中独立演进，但入口和文档应区分“业务工作流模型设计”与“BPMN/XML 建模”，避免把可编译的业务模型误认为完整 BPMN 能力。
- 在后端正式 Schema 发布前，跨仓库的模型兼容通过版本化 Schema/样例副本和契约检查维护；后端契约来源明确后，前端类型和映射须跟随它更新。
- 未知业务数据采用保守的只读/禁编译策略，避免旧版设计器静默丢弃未来语义或生成不完整流程。

## 2026-11-16 增补：独立业务模型 SDK

新增框架无关的 `@workflow/sdk`，承接标准模型类型、JSON Schema 2020-12、离线结构/语义校验和不可变的编译 JSON 导出。`@workflow/designer` 和宿主单向依赖 SDK，名称、坐标默认值、开始/结束数量、普通回路、连接交互与设计稿信封继续属于编辑层。协议语义不再由节点默认定义重复维护；扩展校验仍由设计器追加。

执行契约基线更新为后端 `/bpmn/spec` version 1 的 2026-11-16 快照。它返回自定义描述，SDK 维护标准 Schema 兼容副本并通过同组示例检查一致性；设计器原 Schema 下载路径是 SDK Schema 的同步副本。规范明确名称、坐标与 flows 可选，故 SDK 不要求它们；设计器仍补齐编辑所需值，已有坐标保留。此增补修正首版将编辑坐标要求视为通用协议必需项的约定。

SDK 支持后端十种语义节点及显式旧类型兼容透传；parallel 尚无画布组件，设计器保留原模型、提示能力限制并阻止编译。SDK 的 warning 不自动阻止导出。未知字段/类型仍形成 error，原始输入不被修改。编辑层只排除流程画布宽高与片段来源等已知元数据，节点布局字段保留，未知业务字段不得被过滤掩盖。

SDK 不请求网络、不生成 XML、不展开子流程前缀、不生成派生节点与 params_rules；鉴权、模板发布和运行时仍由宿主与后端承担，符合 ADR-0004。接入方负责自有 XML/JSON 到标准模型的转换，平台不维护合作方专属适配器。SDK 包版本、隐式模型 v1 与设计稿信封版本分别演进。首版交付可独立安装的 ESM tgz，不实际发布 registry，设计器保持 private。

## 2026-11-17 增补：函数定义与显式业务网关客户端

用户要求业务系统通过函数及参数同时使用定义和运行能力，因此将 0.1 的“SDK 整体不请求网络”范围扩展为三个独立入口：根模型入口与新增 definition 入口保持纯离线；新增 client 入口仅在显式调用操作时通过宿主注入的 request 访问业务网关。导入和创建客户端均不发送请求，不依赖 Vue、Axios、Pinia 或设计器。原模型 v1、Schema 和导出兼容，函数构造的额外结构约束不反向施加于原始模型。

客户端组织编译/发布、规则驱动的启动/完成、消息及版本/任务/进度/历史/分配查询。宿主拥有基础地址、实际 HTTP 状态与鉴权；设计器包继续仅依赖模型模块，宿主编译/发布回调通过 adapter 复用 client。启动普通值与完成/消息 value 包装分别处理；表单保留原 key，公共 vote 不加前缀；不自动重试写请求或用最新模板解释旧任务。

ADR-0004 的引擎执行、最终参数校验、安全、租户、审计、worker 与回调职责不变。SDK 不生成 XML、params_rules 或展开子流程，不内置凭据。真实引擎证据与环境差异分开记录在 SDK 验证文档；未验收的后端场景不因此被视为可用。

## 2026-11-18 增补：业务设计器并行网关

业务设计器沿用后端与 SDK 已有的 parallel，增加第十种可编辑节点，不升级模型 v1 或设计稿信封。分流/汇合角色由入出线决定，不增加模式字段。并行出线必须无 branch 和 conditionExpression；非法导入保留原字段并阻止编译，修复通过显式可撤销操作完成。节点编辑、历史、宿主扩展和只读保护继续使用既有入口，宿主连接扩展只能收紧基本连接限制。

已验证基本节点编辑、设计稿往返、真实拖线、非法条件显式修复、嵌套检查及片段复用，并用新设计器产物验证两种办理顺序与嵌套等待。静态结构检查仅针对可证明的无回路结构化区域，复杂条件或回流给出范围 warning；不套用函数 DSL 的所有限制。分层证据见设计器并行网关验证说明。引擎与消息投递仍遵循 ADR-0004，不因画布可编辑而视为运行验收通过。

# 业务流程预览共用渲染能力，提供组件和 iframe 页面

**Status: proposed**

业务系统需要在选择已发布任务模板时查看业务环节与路径。采用轻量预览组件和独立 iframe 预览页共用渲染能力的方向，沿用业务工作流模型及业务节点、连线展示，避免从编译产物反推原始业务模型；Vue 宿主可直接集成组件，其他宿主可嵌入页面。

用户已选择组件与 iframe 两种接入形态，并确认保留业务节点坐标并适应画布、缺失业务模型时明确提供 BPMN 备用入口、保留基本看图交互且子流程先展示外层节点。预览采用统一主题，首版沿用现有 displayJson 发布结构，不承担完整设计稿状态还原。

用户随后重新讨论 iframe 的取数职责，提出自行取数以降低业务方接入成本。当前修订建议是 Vue 组件继续由宿主单向传入模型，iframe 根据 templateKey 获取详情，优先通过业务系统同源网关接入当前用户权限；它不与组件共享 API 依赖。该修订仍待确认部署和鉴权边界，先前宿主通过 postMessage 传入完整模型的方案不再作为最终实施前提。

本文仍为 proposed：iframe 部署鉴权、来源与通信契约、版本一致性边界、未知节点及缺失布局处理和交付范围正在访谈。详细方案与待定事项见 [业务流程预览接入方案](../workflow-preview.md)；完整契约确认前不视为已接受的实施决定。本决策承接 ADR-0005 中业务模型、设计稿信封与宿主 API 的职责划分。

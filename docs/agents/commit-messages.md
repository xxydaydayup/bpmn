# Commit 约定

创建 Git 提交前，使用以下格式编写提交标题：

`类型(范围): 中文摘要`

- 类型使用小写英文，并准确描述改动性质：`feat`（新增能力）、`fix`（修复问题）、`docs`（文档）、`refactor`（不改变外部行为的重构）、`test`（测试）、`build`（构建或依赖）、`ci`（持续集成）、`chore`（其他维护）。
- 范围填写受影响的功能或文档区域，如 `workflow`、`designer`、`camunda`、`agents`、`cleanup`。改动横跨多个区域且无法合理归入单一范围时，可以省略范围。
- 摘要用中文简洁说明提交产生的结果；保留必要的代码、产品或协议名称，不加句号，不写成笼统的“更新代码”或“修复问题”。
- 一个提交聚焦一个目的。需要补充背景或影响时，在标题后空一行写正文；关联工单时添加准确的工单引用，不猜测或虚构编号。
- 只有用户明确要求创建提交时才执行提交。提交前检查暂存区，确认只包含本次授权范围内的改动；已有的无关或未提交改动不得顺带提交。

示例：

- `feat(workflow): 接入业务任务接口与入口控制`
- `fix(designer): 修复导入后节点标签重绘`
- `docs(cleanup): 清理过时规则与历史文档`
- `test(camunda): 增加代理烟测`

# BPMN 流程设计器优化审查

> 调研日期：2026-09-22
>
> 范围：仓库当前实现、`package.json`、`README.md`、`docs/designer-styling.md`、`src/bpmn/*` 与现有测试。生态候选按 bpmn.io 官方项目命名整理；新增依赖前仍需以目标版本的 peerDependencies、XML 往返和浏览器回归为准。

## 当前基线

当前设计器已经形成一条可用的前端建模闭环：

- Vue 3 + TypeScript + `bpmn-js 18.6.1`，Camunda 7 moddle 与 behaviors 已接入。
- 节点库、拖入/点击创建、原生 context pad、撤销/重做、XML 导入/编辑/复制/导出已经可用。
- 自定义 Vue 属性面板支持人工任务分配、表单引用、多实例、服务任务执行方式、排他分支条件和默认分支。
- 基础流程检查、六个模板、ELK 自动布局、布局命令整体撤销/重做和错误导入恢复已经覆盖。
- 自定义任务卡片、中文标签、Tabler 本地 SVG 和响应式工作区已经建立；样式默认值集中在 `theme.ts`。

本次实测：`pnpm test` 通过 32 项，`pnpm build` 通过。构建产物提示 ELK worker 约 1.6 MB，设计器主 chunk 约 697 kB。

## 已确认的产品边界

- 执行契约先锁定 Camunda 7。
- 样式分为预设主题与元素级覆盖；主题使用固定 token，不开放任意 CSS/字体注入。
- 元素级覆盖存入独立 JSON，不写 BPMN XML；导出格式为 BPMN 与 JSON 配套文件。
- 缩略图、网格、吸附、对齐和分布从顶部工具栏进入，多选后支持批量操作。

## 优先优化项

### P0：先补“可用性与数据安全”

1. **脏状态、自动保存和版本**
   当前页明确提示“修改未自动保存”，离开页面没有草稿保护、版本号、恢复点或冲突提示。应增加 `dirty` 状态、离开拦截、浏览器本地草稿兜底，并为后端保存预留 `revision`、`updatedAt`、设计稿原文和部署产物版本。

2. **导入能力分级**
   现在导入警告以一条文本提示，用户无法知道哪些节点、事件定义或扩展被跳过。建议在导入后展示“保留/降级/不支持”清单，并提供只读保真模式；导出前明确哪些内容可被 Camunda 7 执行、哪些只保证 XML 保留。

3. **校验分层**
   `validation.ts` 适合做结构和 Camunda 必填项检查，但条件表达式、用户有效性、监听器和运行时变量仍未验证。应拆成：实时设计 lint、导出阻断规则、部署前引擎校验三层，并允许规则配置严重级别和快速修复。

4. **Renderer 升级隔离**
   `BusinessRenderer` 直接调用 `bpmnRenderer.handlers['bpmn:Task']` 的内部 handler。升级 bpmn-js 时容易失效，应封装 adapter，并增加任务标记、多实例标记、显式颜色、标签重绘的浏览器 smoke test。

5. **可访问性与键盘操作**
   现有外围控件已有 focus 样式，但画布节点、选中状态、校验结果和错误恢复还需要统一的 ARIA/live region、键盘快捷键说明、放大镜和高对比度验收。

### P1：补齐设计平台能力

- **布局和导航**：缩略图、网格开关与吸附、对齐/分布、批量移动、路由清理、锁定节点、框选批量操作。
- **BPMN 覆盖**：定时器/消息/信号/错误/补偿/边界事件、泳池泳道、子流程、调用活动、数据对象、注释、事件网关和包容网关。每增加一种类型，都要同步节点库、Renderer、属性快照、校验、布局和 XML 回导测试。
- **Camunda 高级字段**：异步前后、排他执行、优先级、重试周期、到期/跟进日期、任务/执行监听器、输入输出映射、错误事件、扩展属性和表单绑定。
- **模板治理**：模板元数据、版本、适用引擎、可部署性、必填变量和迁移提示；把当前硬编码节点默认值逐步迁移到可版本化模板。
- **协作与发布**：设计稿保存、版本比较、评论、权限、发布前检查、部署记录、回滚和环境差异。
- **预览与运行**：把 token simulation 放在独立的只读预览路由，避免运行态标记污染设计稿样式。

## 自定义样式方案

当前样式边界是合理的，但需要从“开发者改常量”升级为三层模型：

1. **主题 token 层**：背景、字体、密度、卡片尺寸、语义色、选中态、网格和连线统一由 `theme.ts` 提供；补充浅色/深色/高对比度主题和字号密度档位。
2. **元素样式层**：用户可选节点/连线的填充色、描边色、标签颜色和密度覆盖。样式写入独立的样式附属 JSON，按流程版本和元素 ID 关联；导出 BPMN XML 时不写入颜色扩展，缺失配置时回退到主题默认值。
3. **语义模板层**：节点默认名称、图标、Camunda 属性、帮助文案和颜色策略由版本化模板管理，不能把业务语义埋在 CSS 类名里。

适合引入的生态库：

| 优先级 | 库 | 用途 | 建议 |
| --- | --- | --- | --- |
| P0 | `diagram-js-minimap` | 大图导航 | 低风险，先接入并统一自定义卡片颜色和预设主题。 |
| P1 | `diagram-js-grid` | 网格显示 | 仅在需要官方网格层时考虑；bpmn-js 已内置网格吸附，当前自绘点阵可先继续使用。 |
| P2 | `bpmn-js-color-picker` | 颜色选择器 | 默认会走 BPMN 颜色建模语义，与本项目 sidecar 决策不一致；优先使用现有 Element Plus `ElColorPicker`，或自行适配为 sidecar 写入。 |
| P1 | `bpmn-js-element-templates` + `@bpmn-io/element-templates-json-schema` | 可版本化节点模板 | 先用于新建节点默认值，再扩展属性面板和模板导入导出。 |
| P1 | `bpmn-js-bpmnlint` + `bpmnlint` | 画布实时规则与问题标记 | 与现有 `validation.ts` 分工，避免重复提示。 |
| P2 | `bpmn-js-properties-panel` / `@bpmn-io/properties-panel` | 高级 BPMN/Camunda 属性 | 不建议立即替换现有 Vue 面板，先评估 provider 能否分阶段共存。 |
| P2 | `bpmn-js-token-simulation` | 运行路径预览 | 独立只读页面使用，不进入样式和部署闭环。 |

图标继续使用本地 Tabler SVG 是低风险方案。若图标规模变大，可评估 `@iconify/vue` 或 `unplugin-icons`，但只打包自托管图标集；不要把用户 SVG 直接注入 Renderer。Tailwind、UnoCSS 或另一套画布 UI 框架不能解决 SVG 几何、marker 和 BPMN DI 持久化问题，不建议为画布引入。

## 推荐落地顺序

1. 脏状态/本地草稿/版本接口、导入降级清单、校验分层和 Renderer adapter。
2. token 主题系统、sidecar 样式模型、深色/高对比度、minimap、键盘/ARIA、样式回归测试。
3. 画布网格开关、已有 grid snapping/align/distribute 能力的工具栏入口、sidecar 导入导出、element templates、bpmnlint。
4. 高级 Camunda 属性、更多 BPMN 类型、保存协作和部署治理。

新增任何样式或插件都要验证：显式颜色优先、DI 几何不丢失、业务 XML 原文保留、撤销/重做完整、Camunda 7 部署可识别，并锁定与 `bpmn-js 18.6.1`、`diagram-js 15.26.0` 匹配的依赖版本。

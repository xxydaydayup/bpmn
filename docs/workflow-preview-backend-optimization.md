# 流程实例预览后端聚合接口优化建议

**状态：后续优化建议，尚未实现。** 本文描述未来可增加的接口，不属于当前可调用的后端 API。当前接入契约仍以[流程预览接入指南](workflow-preview-embedding.md)列出的只读接口为准。

## 背景

流程图组件本身只需要业务流程模型 displayJson、模板/版本信息，以及按节点 ID 对应的活动状态。模板预览已有 GET /v1/template/{key} 可以返回所需模板快照。

实例预览需要先拿到实例实际使用的 processDefinitionId，再找到该定义对应的准确模板历史版本，并查询当前或历史活动。这些数据分布在业务模板服务和 Camunda 查询接口中，因此前端适配层需要串联多个只读请求、分页查找，并核对快照和实例的定义 ID。模板索引没有直接命中时，还可能逐个读取可见模板的历史索引。这样能保证旧实例不会误用最新模板，但查找和组装逻辑落在了前端，模板较多时请求也会增加。

## 建议方案

由后端提供一个专用于只读实例预览的聚合接口：

~~~text
GET /api/workflow-preview/instances/{instanceId}
~~~

调用方只传实例 ID。后端使用当前登录身份读取实例、解析其准确流程版本并整理活动状态，前端收到响应后负责绘制，不再自行遍历模板和历史记录。接口只读，不启动、办理、暂停或修改实例。

建议成功响应包含以下信息：

~~~json
{
  "instance": {
    "id": "instance-123",
    "state": "RUNNING",
    "ended": false,
    "businessKey": "leave-2026-001",
    "processDefinitionId": "leave:3:definition-id"
  },
  "template": {
    "key": "leave",
    "name": "请假审批",
    "version": 3,
    "processDefinitionId": "leave:3:definition-id",
    "displayJson": { "nodes": [], "edges": [] }
  },
  "activities": [
    { "activityId": "manager_approval", "status": "active" },
    { "activityId": "submit", "status": "completed" }
  ],
  "bpmnXml": null,
  "warning": null
}
~~~

字段名可按后端 API 约定调整；上例表达的是最小数据边界。activities 中的 activityId 使用 BPMN 节点 ID，而不是一次执行生成的 activity-instance ID；状态建议限定为 active、completed、canceled。运行中实例通常返回当前活动，已结束实例返回接口明确记录的历史完成/取消活动。接口没有提供的活动或连线执行路径不应由后端或前端臆测。

## 后端职责

1. 用当前访问者身份检查该用户是否能查看实例及其所属租户；不能仅凭实例 ID 放行。若下游流程引擎使用服务身份访问，后端仍须在自身或授权网关中完成真实用户的资源权限校验。
2. 查询运行实例；不存在运行记录时按现有策略查询历史实例。取实例自身的 processDefinitionId 作为版本匹配依据。
3. 找到与该 processDefinitionId 完全匹配的模板历史快照，并核对流程定义 ID、模板 key 和版本。禁止仅按流程 key 取最新版本，也不要把不匹配的模型交给前端。
4. 对运行实例整理当前活动；对已结束实例整理历史活动及明确的取消状态。检查活动记录确属当前实例和流程定义。
5. 业务模型缺失或不可用时，只能查询相同 processDefinitionId 的 BPMN XML 作为可选备用图，并在 warning 中说明情况。模板模型和 XML 都不可用时仍可返回实例元信息与活动数据，让前端呈现清楚的部分空态。
6. 不返回流程变量、表单内容、审批意见、引擎管理员凭据或预览用不到的敏感字段。响应按用户和租户隔离缓存；建议使用 Cache-Control: no-store。

认证失败、权限不足、实例不存在及下游故障应沿用业务系统既有 HTTP 错误规范，并让前端能区分登录失效、无权、找不到和暂时不可用。若产品策略需要隐藏资源是否存在，可对无权资源统一返回 404。

## 前端职责

前端调用上述接口一次，展示实例/模板元信息，把 template.displayJson 和 activities 转成现有预览组件接收的模型与节点状态；如业务模型无法绘制且响应中有 bpmnXml，仍可提供显式的 XML 备用视图。前端继续负责加载、错误、重试、请求取消、迟到响应隔离和只读交互，不负责推断或补造服务端未返回的版本与活动信息。

模板预览继续使用现有 GET /v1/template/{key}，前提是该接口返回同一模板版本的 displayJson、XML 与元信息，并由服务端按当前用户授权。若现有模板详情缺少字段或权限保护，应扩展/加固该接口，而不是默认再增加一个重复的模板预览接口。

## 验收要点

- 运行和历史实例均返回实际流程定义版本，不会把新版本模型用于旧实例。
- 使用无权用户、错误租户和其他用户可见实例 ID 时，服务端逐请求拒绝越权访问；直接请求聚合接口也受保护。
- 运行实例只标记当前活动；历史实例只标记接口明确返回的完成或取消活动，不伪造执行路径。
- 当精确业务模型缺失时，XML 备用图若存在，必须来自同一 processDefinitionId。
- 响应不包含流程变量、表单或凭据，并且不会跨用户/租户复用缓存。
- 前端以一个实例预览请求即可获得绘图需要的数据；失败和部分数据状态可明确呈现。

这项聚合接口优化不会替代生产同源代理、登录会话透传、租户/资源授权、HTTPS、CSP frame-ancestors 和部署环境验收；这些仍是实际业务系统必须落实的安全与部署工作。

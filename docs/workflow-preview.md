# 业务流程预览接入方案

状态：Q2～Q4 已确认；第二轮组件形态契约已确认（见下），Q1 iframe 部署鉴权与 iframe 页延后收敛，尚未实现。记录日期：2026-11-17，最近更新：2026-11-23。

## 目标与已确定方向

业务系统选择已发布任务模板后，可查看与该模板关联的业务流程图。提供轻量预览组件和独立 iframe 预览页，两者共用业务节点、连线及模型映射能力。用户已选择这一接入方向，Q2～Q4 已确认；随后提出 iframe 自行取数能否降低业务方接入成本，Q1 据此重新讨论。当前修订建议是组件继续接收模型，iframe 默认按模板标识自行取数；部署与鉴权方式尚待确认。第二轮其他建议仍待确认。

本文使用“已发布任务模板”指接口列表中供业务系统选择和发起的对象；设计器中用于新建设计稿的预设仍称“流程模板”。术语见 [CONTEXT.md](../CONTEXT.md)，架构方向见 [ADR-0006](adr/0006-embeddable-workflow-preview.md)。

## 核实过的当前能力

- 业务设计器宿主发布时将裸业务模型放入 `displayJson`，gateway 使用 `display-json` 表单字段提交；当前没有随此调用保存 `editor`。
- 模板列表、详情的前端接口层接受 `displayJson`；详情页当前仅通过 `ReadOnlyProcessDiagram` 展示 BPMN XML。
- 本次会话此前对当前配置后端的只读查询返回 16 个模板，其中 8 个的列表与详情包含裸业务模型，16 个详情均有 XML，未发现设计稿信封。该数字只是当时环境的观测结果，不是接口保证。
- 设计器包已有业务节点、连线、业务模型与画布的映射；尚未提供 `WorkflowPreview` 或独立预览路由。
- 当前 `readonly` 需要补齐节点级拖拽、连接和底层键盘删除等边界；不能将现有完整编辑器简单标记只读后直接当作预览产品交付。以上交互缺口来自源码检查，尚未通过浏览器复现。
- 设计器包当前是 private workspace 包，依赖同 workspace 的 SDK；对其他仓库的安装与发布方式尚需明确。
- 当前所有业务页面路由位于 `AppLayout` 下；独立嵌入页需具有自己的页面入口。当前请求封装没有生产登录态或 iframe 通信约定。

## 建议的职责分工

以下为可供确认的设计草案，名称和路径均为拟议值。

| 层次 | 职责 | 拟议入口 |
| --- | --- | --- |
| 预览组件 | 接收业务模型或受支持的设计稿信封，在内部管理视口，绘制只读业务图；不请求模板接口 | `WorkflowPreview`，独立预览导出入口 |
| 预览页面 | 为 iframe 提供无工作台导航的页面，按 URL 中的模板标识读取详情，管理加载、错误和备用图；取数使用已配置的受控 API 与当前访问者的有效身份（修订建议） | `/embed/workflow-preview?templateKey=...` |
| Vue 业务系统 | 按自身权限查询选中模板，将数据单向传给组件，处理外部加载与错误 | 组件集成示例 |
| 其他业务系统 | 将选中模板的标识写入 iframe 地址，按选中项更新地址；配置网关与会话接入（修订建议） | iframe 集成示例 |

预览组件复用业务节点与连线的展示实现，但应核查导入依赖，避免将编辑器工具栏、属性编辑器、历史记录、编译和发布功能引入预览入口。具体抽取方式通过实现前的模块依赖检查确定。

### Q1 修订：自行取数与部署鉴权

自行取数能让业务方从管理整份业务模型和消息生命周期，简化为设置 iframe 地址。预览页读取 templateKey 后调用当前已存在的 `GET /api/v1/template/{templateKey}`，拿到 displayJson 交给纯展示组件，BPMN 备用入口使用同一详情响应中的 XML。加载、取消、错误重试和模型适配由预览页统一负责。

推荐首版采用同源子路径或反向代理接入：业务系统的域名下开放预览页及受控取数路径，浏览器在 Cookie 的 Domain、Path、SameSite 等条件满足时携带该域会话，由网关校验当前用户并将身份映射到模板服务。反向代理本身不会自动完成登录与租户权限对接；如宿主使用 JS 管理的 Bearer Token，iframe 也不会自动继承它，需要额外的会话桥接或授权约定。不能用统一的高权限代理账号代替访问者权限判断。

若采用集中域名跨域嵌入，业务方同样可以只传模板标识，但需预览平台拥有可用的登录会话或短效只读授权；跨站 Cookie 的可用性受浏览器策略影响，不能将“主页面已经登录”视为 iframe 自动登录。长期 token、后端账号和密钥不作为 URL 参数。

部署选择待确认：是否接受先采用业务系统同源路径，通过其网关接入当前用户权限，使业务页面仅需设置含 templateKey 的 iframe src。若必须集中域名部署，则下一步再选择 SSO 或短效授权方式，不同时要求接入两种生产鉴权模式。

### iframe 取数与通知草案（Q5，随 Q1 修订）

- 组件接口拟为单向 `model` 输入，模板名称、key、version、processDefinitionId 作为预览上下文；不提供写回业务模型的事件。BPMN 备用展示由宿主适配层提供，避免业务图组件直接依赖 XML 渲染器。
- iframe 页面为独立路由，不显示工作台侧栏；读取 URL 中的 templateKey，使用部署配置指定的 API 读取详情。URL 不承载任意 API 地址、长期登录令牌或完整模型。直接打开时也需通过相同的用户权限校验；未传模板标识时显示明确提示。
- 部署通过显式允许来源配置限制宿主 origin，并给出反向代理 `frame-ancestors` 等嵌入配置示例。同源集成同样验证来源；不把任意 URL 参数当作来源授权。
- 基本展示通过 iframe 地址即可接入；postMessage 作为可选通知通道，后续如需无页面重载地切换模板，再评估增加命令。启用消息时双向校验准确 origin 与对应窗口，协议携带版本和请求关联标识。
- 选择变化时业务方更新 src，预览页自行请求相应详情；页面内如发生参数切换则取消旧请求，并以递增序号隔离旧响应。刷新和切换后，元信息、业务模型与备用 XML 一起更新。
- 预览页统一展示加载、无权限、不存在、模型缺失、渲染失败及重试状态；失败时清除旧图。有有效身份且有权限时，直接打开同一地址也可看图。
- 已确认的 XML 备用入口使用与业务模型相同的详情快照；展示与业务图明确区分。预览页不从模型中的任意地址加载资源。

### 模板版本边界（Q6）

当前前端模板详情接口按 templateKey 查询，启动接口输入也只有 taskKey/templateKey，没有已声明的 version 或 processDefinitionId 锁定参数。预览传入版本号不等于后端会按该版本启动。

建议直接集成组件时由宿主获取完整详情快照；iframe 自行取数时由预览页获取，并统一更新名称、版本、模型及备用 XML。若需与业务列表核对，可由宿主提供期望的流程定义 ID 作为过期检查条件，发现不一致则明确提示；该检查不等于历史版本查询或锁定启动版本。是否通过可选消息向宿主通知实际版本，在 Q1 部署方式确定后与 Q5 一起收敛。预览打开后保持快照，直到显式刷新或切换。

宿主在发起前重新核对版本可减少过期选择，但查询与启动之间仍存在竞争窗口。严格保证“看到哪个版本就执行哪个版本”需要后端支持按不可变定义版本发起或执行条件校验，建议作为独立后续需求；首版不修改启动接口，也不提供实例进度或历史轨迹。

### 显示兼容策略（Q7）

先区分模型缺失、模型为空、结构错误和可展示但能力不完整。未知节点不静默删除，使用名称和原始类型占位并提示；未知字段保留但不自动变成可见属性，也不执行任何表达式。

裸模型不包含坐标是 SDK 允许的情况。建议坐标完整时沿用原值；坐标缺失时在副本上自动布局并提示“使用预览布局”，不写回输入、不保存设计稿，也不触发编译发布。自动布局按需加载，正常有坐标预览不加载 ELK。受支持信封的路由点可复用，但主题和初始视口仍遵循第一轮已确认的统一预览规则。

无法可靠确定连线归属的数据（如重复或空节点 ID、悬空 source/target）应报错并清除旧图，不拼凑误导性的部分流程。无法识别的未来信封不按旧格式悄悄解释；错误状态可进入明确标注的 BPMN 备用视图。子流程首版只展示外层节点和步骤数量，不提供内部导航。

### 组件交付与宿主集成（Q8）

建议保持现有设计器包，增加 `@workflow/designer/preview` 和对应 CSS 的独立入口，避免要求接入方复制源码或另建一套节点实现。当前节点展示从节点注册表导入元信息，而注册表同时引用 PropertyEditor；实现时需拆出共享展示元信息，确认预览入口不会连带引入编辑器、模板库和属性面板。

提供可在其他仓库安装的设计器与 SDK 配套 tgz，并列明 Vue、Vue Flow peer dependency 范围。包安装方式是可选项：iframe 接入方使用部署后的预览页地址和部署鉴权说明，有需要时接入通知事件。首版不执行 npm 发布，也不需要改动业务 JSON 或后端保存字段。

建议当前业务页在选择模板后展示预览，详情弹窗复用同一适配层。附纯 HTML 宿主示例，演示设置和切换带 templateKey 的 iframe src、可选加载通知、错误反馈和 XML 备用入口；附 Vue 单向输入示例，说明固定容器高度与弹窗打开后的自适应。验收包括连续快速切换、容器缩放、未知/缺失数据、权限身份、可选消息来源、页面重载和只读键盘/拖拽交互。

## 确认后实施顺序

1. 固定数据、版本和兼容边界，完成本方案与 ADR 的确认。
2. 抽取共享展示能力并实现预览组件，关闭所有修改入口，隔离预览状态与输入对象。

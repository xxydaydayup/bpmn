本文记录 2026-11-18 契约下的能力与验证，包含当时子流程 ID 逐层添加前缀的行为。2026-11-20 后端已取消该规则，当前节点和连线 ID 必须在整个模型中唯一并原样用于活动标识，见[设计器当前说明](../README.md)。以下旧编译和运行证据按原契约保留，不作为新 ID 契约的验收结果。

2026-11-18，业务设计器已支持第十种内置节点 parallel，沿用模型 v1 和设计稿信封版本，无需迁移旧设计稿。

## 使用

在「流程控制」中点击或拖入「并行网关」，或在「流程模板」中选择「并行审批」。模板依次包含提交、财务/法务两条独立人工任务、汇合、归档和结束。通过既有宿主编译和显式发布入口生成可发起模板；发起时按后端 params_rules 给各节点填写办理人。

一个入线多个出线会激活全部分支，多个入线会等待全部到齐，多入多出先等待再分流。网关自身不生成待办，也不新增审批参数。汇合表示分支完成，不表示所有人同意；同一多人审批节点的并行办理仍是独立能力。

并行出线不能带 branch 或 conditionExpression，进入网关的合法条件流可以保留。导入或重接留下的非法条件会原样保留并阻止编译/发布；选中问题连线后点击「清除并行出线条件」一次移除两个字段，可一次撤销/重做。其他未知数据不会一并删除，仍按既有策略保留并阻止编译。

子流程片段模式支持并行结构，允许省略开始/结束。保存后可重新打开，主流程引用独立快照，库内容变化不会自动影响已有快照。递归嵌入沿用后端逐层前缀化；片段来源和画布元数据不进入编译输入。

## 静态检查范围

简单、同层、无回路的结构化并行会检查公共并行汇合、提前结束、绕过汇合和区域交叉；嵌套及递归子流程按各自区域判断。条件选择、普通节点多出线及回流只给出范围明确的 warning，不能据此声称已证明无死锁。SDK 字段/引用/出线协议以及既有普通回路与跨作用域限制继续生效。
